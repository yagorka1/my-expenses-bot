# my-expenses-bot

Telegram-бот для записи трат. Данные хранятся в Firestore (тот же проект, что и у `expenses-mobile`),
доступ через Firebase Admin SDK. Сервер `expenses-server` боту больше не нужен.

## Переменные окружения

| Переменная | Описание |
| --- | --- |
| `BOT_TOKEN` | токен бота |
| `ALLOWED_USERS` | Telegram id через запятую — кто может пользоваться ботом и получает рассылки |
| `FIREBASE_SERVICE_ACCOUNT` | JSON ключа сервисного аккаунта одной строкой (или `GOOGLE_APPLICATION_CREDENTIALS` — путь к файлу) |
| `IS_LOCAL` | `true` — long polling, иначе webhook |
| `DOMAIN`, `PORT` | для webhook |
| `MONGODB_URI`, `DNS_SERVERS` | только для скрипта миграции |

Ключ: Firebase console → Project settings → Service accounts → Generate new private key.
Файл ключа не коммитить (он в `.gitignore`).

## Перенос данных из MongoDB

```bash
npm run migrate -- --dry-run   # проверить, ничего не пишет
npm run migrate                # скопировать categories, subcategories, expenses
```

Id документов сохраняются, поэтому дублей не будет. Траты копируются, только пока в Firestore их нет:
повторное копирование отменило бы правки, сделанные в приложении, и вернуло бы удалённые там траты.

**Больше не запускать.** Категории теперь добавляют и переименовывают в приложении (раздел «Категории»), а миграция
перезаписывает категории и подкатегории из MongoDB и вернула бы старые названия.

## Категории в тратах

Трата ссылается на категорию и подкатегорию только по `categoryId` / `subcategoryId`, названия бот, приложение и
выгрузка в таблицу берут из `categories` / `subcategories`. Поэтому переименование сразу видно везде, и в отчётах
переименованная категория остаётся одной строкой.

У старых трат ещё лежат копии названий `categoryName` / `subcategoryName`: пока они есть, ими пользуются только
как запасным вариантом, если id не находится. Убрать их и починить id:

```bash
npm run normalize-categories             # отчёт: сколько трат исправится и какие не сопоставить; ничего не пишет
npm run normalize-categories -- --apply  # записать; старые значения сначала сохраняются в backups/
```

Подкатегория ищется по `subcategoryId`, если его нет — по названию внутри категории; `categoryId` выставляется по
подкатегории. Траты, которые не удалось сопоставить, не трогаются и остаются с названиями.
Запускать после того, как задеплоены новые бот, приложение и `Code.gs`: старые версии читают названия из трат.

## Перестройка категорий

Разовый перевод категорий на структуру, совпадающую со статьями таблицы бюджета (список — в
`src/scripts/remap-categories.ts` и `categories-restructure.md` в `expenses-mobile`):

```bash
npm run remap-categories             # отчёт: новая структура, сколько трат куда переедет; ничего не пишет
npm run remap-categories -- --apply  # записать; категории, подкатегории и старые id трат сначала сохраняются в backups/
```

Слитые подкатегории удаляются, их траты переезжают в оставшуюся. Если хоть одно название из списка не найдено или
какая-то подкатегория не попала в список, скрипт ничего не пишет. Перед запуском откройте приложение на всех
телефонах с интернетом: офлайн-трата со старой подкатегорией после её удаления не пройдёт правила.
Таблицу обновить тем же днём (пункт меню «Обновить статьи» в `sheet-sync`).

## Доступ к приложению

Человек один раз входит в приложение (email или Google), после этого:

```bash
npm run add-member -- someone@gmail.com
```

## Запуск

```bash
npm run dev      # локально (nodemon + ts-node)
npm run build && npm start
```

Нужен Node 22+ (требование firebase-admin).
